Chapter 11 · Hardware Design

Control & Simulation

So far every converter has run at a duty cycle we calculated. Real converters never get to do that: the sun changes, the grid voltage wanders, the load steps, and components drift. Feedback control measures what is happening and adjusts the duty cycle to keep voltages and currents where they should be. This chapter models the boost converter, designs its control loops, and simulates it in Python, so you can see what happens with and without control.

Averaged models

A switching converter jumps between two circuits every few microseconds. To design a controller we care about how it behaves over many periods, so we average each equation over one switching period, weighting each switch state by the time spent in it. For the boost converter, with d the duty cycle and d' = 1 - d:

Averaged boost converter model

L \frac{d i_L}{dt} = v_{in} - d' \, v_{out}, \qquad C \frac{d v_{out}}{dt} = d' \, i_L - \frac{v_{out}}{R}

Setting the derivatives to zero gives back Chapter 4's results: V_{out} = V_{in}/D' and I_L = V_{out}/(D'R).

The averaged model hides the ripple but captures everything slower than the switching frequency: start-up, load steps, oscillations. It also runs hundreds of times faster than a switch-by-switch simulation, which is why it is used for control design.

The boost converter's transfer function

Linearising the averaged model around an operating point gives the transfer function from a small change in duty cycle to the output voltage:

Boost control-to-output transfer function (voltage mode)

G_{vd}(s) = \frac{V_{out}}{D'} \cdot \frac{1 - s/\omega_z}{1 + \dfrac{s}{Q\omega_0} + \dfrac{s^2}{\omega_0^2}}, \qquad \omega_z = \frac{D'^2 R}{L}, \quad \omega_0 = \frac{D'}{\sqrt{LC}}, \quad Q = D' R \sqrt{\frac{C}{L}}

A double pole from L and C, and a zero in the right half-plane (RHP).

For a standalone version of our boost (300 V to 400 V, 3 kW, so R = 53.3 Ω, with L = 750 µH and C = 100 µF):

  • The double pole sits at f_0 = 0.75/(2\pi\sqrt{750\,\mu\text{H} \times 100\,\mu\text{F}}) = 436 Hz with Q = 14.6: a sharp, barely damped resonance.
  • The RHP zero sits at f_z = 0.75^2 \times 53.3/(2\pi \times 750\,\mu\text{H}) = 6.4 kHz.

The right-half-plane zero

Raise a boost converter's duty cycle and, at first, the output voltage falls: the diode now conducts for a shorter part of each period, so less of the inductor's current reaches the output. Only after the inductor current has grown does the output rise. A controller that reacts quickly to a falling voltage by raising D makes the dip worse. The RHP zero adds phase lag like a pole while increasing gain like a zero, and it cannot be cancelled. It limits any loop that controls the boost's output voltage to a bandwidth of roughly a fifth to a tenth of f_z, and it moves lower at heavy load, where R is small.

Current-mode control

Controlling the output voltage directly through the duty cycle (voltage-mode control) means fighting both the resonant double pole and the RHP zero. Almost every power converter above a few hundred watts instead uses cascaded control: a fast inner loop regulates the inductor current, and a slower outer loop sets that current's reference to regulate the voltage.

Above the LC resonance, the inductor current responds to duty cycle almost like a pure integrator, since L\,di_L/dt \approx V_{out} \, \Delta d:

Inner current loop

G_{id}(s) \approx \frac{V_{out}}{sL}, \qquad K_p = \frac{2\pi f_c L}{V_{out}}, \qquad K_i = K_p \cdot 2\pi f_{z,PI}

A PI controller with crossover f_c and its zero f_{z,PI} about a decade lower.

With f_c = 5 kHz: K_p = 2\pi \times 5000 \times 750\,\mu\text{H}/400 = 0.059 per ampere and, with the PI zero at 500 Hz, K_i = 185 per ampere-second. The outer loop then sees a much simpler plant: a current source feeding the capacitor and load, D'/(sC) near its crossover. A 200 Hz crossover needs K_{p,v} = 2\pi \times 200 \times 100\,\mu\text{F}/0.75 = 0.17 A/V, and placing the PI zero at the load's own pole, 1/(\pi R C) = 60 Hz, removes the slow tail that a lower zero would leave.

Peak current mode and slope compensation

An analog alternative turns the switch off when the inductor current reaches a peak set by the voltage loop: cycle-by-cycle current limiting for free. But for duty cycles above 0.5 it is unstable: a small current disturbance grows each period (subharmonic oscillation). The fix is to add an artificial ramp to the sensed current.

Slope compensation

m_a \ge \frac{m_2}{2}, \qquad m_2 = \frac{V_{out} - V_{in}}{L} \;\;(\text{boost down-slope})

Enough compensation for every duty cycle the converter will meet.

Our boost at D = 0.25 does not need it, but at dawn with the PV string at 180 V (D = 0.55) it would: m_2 = (400 - 180)/750\,\mu\text{H} = 0.29 A/µs, so the ramp must add at least 0.15 A/µs.

Simulating the boost converter in Python

The script below models our boost converter twice. The first function simulates every switching event with ideal switches, starting from zero with a fixed duty cycle of 0.25 and no control. The second uses the averaged model with the cascaded PI controllers designed above, running once per switching period like a digital controller, and steps the load from 1.5 kW to 3 kW.

# /// script
# requires-python = ">=3.10"
# dependencies = ["matplotlib"]
# ///
"""Simulate the 3 kW PV boost stage: open-loop switching model and closed-loop averaged model."""
import math

VIN, L, C, FS = 300.0, 750e-6, 100e-6, 50e3   # input voltage, inductor, output capacitor, switching frequency
R_FULL, R_HALF = 400.0**2 / 3000, 400.0**2 / 1500   # load resistance at 3 kW and 1.5 kW


def switched(duty, t_end, dt=1e-7):
    """Switch-by-switch model with an ideal switch and diode, starting from zero."""
    i_l, v_o, t, ts = 0.0, 0.0, 0.0, []
    while t < t_end:
        on = (t * FS) % 1.0 < duty
        v_l = VIN if on else VIN - v_o                 # inductor voltage in each switch state
        i_l = max(i_l + v_l / L * dt, 0.0)             # the diode blocks reverse current (DCM)
        i_c = (0.0 if on else i_l) - v_o / R_FULL      # capacitor current
        v_o += i_c / C * dt
        t += dt
        ts.append((t, i_l, v_o))
    return ts


def averaged_closed_loop(t_end, t_step, dt=1e-6):
    """Averaged model with cascaded PI control: outer voltage loop, inner current loop."""
    kp_i, ki_i = 2 * math.pi * 5e3 * L / 400, 2 * math.pi * 5e3 * L / 400 * 2 * math.pi * 500   # 5 kHz current loop
    kp_v = 2 * math.pi * 200 * C / 0.75; ki_v = kp_v * 2 * math.pi * 60                        # 200 Hz voltage loop, PI zero at 60 Hz
    v_ref, i_l, v_o = 400.0, 3000 / 2 / VIN, 400.0                 # start in steady state at 1.5 kW
    int_v, int_i, duty, t, ts = i_l, 0.0, 0.25, 0.0, []
    n_ctrl, k = round(1 / FS / dt), 0
    while t < t_end:
        if k % n_ctrl == 0:                                          # digital controller runs once per switching period
            e_v = v_ref - v_o
            int_v += ki_v * e_v / FS
            i_ref = kp_v * e_v + int_v
            e_i = i_ref - i_l
            int_i += ki_i * e_i / FS
            duty = min(max(1 - VIN / v_o + kp_i * e_i + int_i, 0.0), 0.95)   # feedforward + PI
        r = R_HALF if t < t_step else R_FULL
        i_l += (VIN - (1 - duty) * v_o) / L * dt
        v_o += ((1 - duty) * i_l - v_o / r) / C * dt
        t += dt; k += 1
        ts.append((t, i_l, v_o))
    return ts


if __name__ == "__main__":
    sw = switched(0.25, 0.06)
    last = [p for p in sw if p[0] > 0.059]
    print(f"open loop: peak Vout {max(p[2] for p in sw):.0f} V, "
          f"final Vout {sum(p[2] for p in last) / len(last):.1f} V, "
          f"inductor ripple {max(p[1] for p in last) - min(p[1] for p in last):.2f} A")
    cl = averaged_closed_loop(0.04, 0.02)
    after = [p for p in cl if p[0] > 0.02]
    v_min = min(p[2] for p in after)
    settle = next(p[0] for p in reversed(after) if abs(p[2] - 400) > 2) - 0.02
    print(f"closed loop: load step 1.5 -> 3 kW, dip to {v_min:.1f} V, back within 2 V after {settle * 1e3:.1f} ms")
    try:
        import matplotlib.pyplot as plt
    except ImportError:
        raise SystemExit
    fig, (a, b) = plt.subplots(2, 1, figsize=(8, 6), constrained_layout=True)
    a.plot([p[0] * 1e3 for p in sw], [p[2] for p in sw]); a.set(title="Open-loop start-up, D = 0.25", xlabel="ms", ylabel="Vout (V)")
    b.plot([p[0] * 1e3 for p in cl], [p[2] for p in cl]); b.set(title="Closed loop, load step at 20 ms", xlabel="ms", ylabel="Vout (V)")
    plt.show()
$ uv run boost_sim.py
open loop: peak Vout 759 V, final Vout 400.1 V, inductor ripple 2.09 A
closed loop: load step 1.5 -> 3 kW, dip to 382.0 V, back within 2 V after 8.1 ms

What the two runs show:

  • Steady state matches the hand design. The switching model settles at 400 V with 2.09 A of inductor ripple, against the 2 A designed in Chapter 4. The small difference comes from the last trace of the start-up oscillation and from the output ripple slightly changing the inductor's slopes.
  • Open-loop start-up is dangerous. The output overshoots to 759 V, almost twice its rated value, enough to destroy 650 V switches and 450 V capacitors. Real converters use soft-start: they raise the duty cycle or the voltage reference gradually, under closed-loop control. Such light damping is normal: the only damping here is the load resistor, and a low-loss converter adds little more.
  • The closed loop is fast and well-behaved. The inductor current reaches its new value within about a millisecond, while the 200 Hz voltage loop recovers the output in 8 ms without overshoot.

Things to try: change C to 50 µF and watch the dip deepen; move the voltage-loop PI zero back to 20 Hz to see the slow tail; or raise the voltage crossover towards the RHP zero until the response starts to ring.

Digital control and its delay

Most converters are controlled by a microcontroller or DSP. Two practical details dominate:

  • Sample at the right moment. Sampling the inductor current at the middle of the on-time (or off-time), synchronised to the PWM counter, returns the average current directly, without filtering out the ripple.
  • Account for the delay. The measurement, the computation and the PWM update together delay the controller's action by about 1.5 switching periods. At crossover f_c that costs a phase of 360^\circ \times 1.5 \, f_c/f_s: 54° for a 5 kHz loop at 50 kHz, too much to leave adequate phase margin. The simulation above updates once per period but does not model this delay, so on hardware the current loop would be designed for 2–3 kHz (22° at 2 kHz) or the switching frequency raised.

The control structure of a two-stage PV inverter

StageLoopTypical bandwidthPurpose
BoostMPPT (Chapter 5)10–100 updates/sChooses the PV voltage reference
PV voltage loop~100–500 HzHolds the PV string at the reference; sets the current reference
Inductor current loop2–5 kHzFast current control and cycle-by-cycle protection
InverterDC-link voltage loop~10–20 HzBalances power: sets the amplitude of the grid current. Kept slow so the 100 Hz ripple of Chapter 6 does not distort the current reference
Grid current loop1–3 kHzTracks a 50 Hz sine with zero steady-state error: a proportional-resonant (PR) controller, or PI controllers in a rotating dq frame
Phase-locked loop~10–50 HzMeasures grid phase and frequency for the current reference

Note the reversal compared with the standalone example: in a PV system the boost regulates its input voltage, because the inverter already holds the DC link. Regulating the input avoids the boost's RHP zero, which lives in the output voltage response.

Simulation tools

  • Python, as above, or with SciPy and the control library for Bode plots and state-space models: free, scriptable, ideal for learning and parameter sweeps.
  • LTspice: free, device-level SPICE models of real MOSFETs and drivers, for switching transients, gate drive and snubbers.
  • PLECS and MATLAB/Simulink: system-level converter simulation with thermal models and automatic code generation for controllers.
Exercise 1: the RHP zero at half load

Where is the RHP zero of the standalone boost at 1.5 kW (R = 106.7 Ω)? Is light or heavy load the harder case for a voltage-mode controller?

Answer

f_z = 0.75^2 \times 106.7/(2\pi \times 750\,\mu\text{H}) = 12.7 kHz, twice as high. Heavy load (small R) brings the RHP zero lower, so full load sets the bandwidth limit.

Exercise 2: delay margin

A current loop with a 2 kHz crossover runs on a controller switching at 50 kHz. How much phase does the 1.5-period delay cost?

Answer

360^\circ \times 1.5 \times 2000/50\,000 = 21.6^\circ. With a PI controller contributing about 6° of lag at a decade above its zero, the loop keeps over 60° of phase margin.

Exercise 3: soft-start in the simulation

How would you change switched() to start safely without closed-loop control?

Answer

Pre-charge the output to the input voltage, as the real diode does when the input is connected (start with v_o = VIN), then ramp the duty cycle from 0 to 0.25 over many resonant periods (for example 20 ms), so the LC resonance is barely excited. In a real converter, closed-loop soft-start of the voltage reference is preferred.

Key takeaways

  • Averaged models describe converter dynamics below the switching frequency and are the basis of control design.
  • The boost's output has a lightly damped LC double pole and a right-half-plane zero at D'^2R/(2\pi L) that limits voltage-loop bandwidth.
  • Cascaded control, a fast current loop inside a slower voltage loop, turns the plant into simple integrators that PI controllers handle well.
  • Peak current mode needs slope compensation above D = 0.5.
  • Digital control adds about 1.5 periods of delay; keep the current loop's crossover well below f_s/10 or compensate.
  • Simulation shows what the equations predict: open-loop start-up nearly doubles the voltage; closed-loop control rides through a full load step with a 4.5 % dip.
