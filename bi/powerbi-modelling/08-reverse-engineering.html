Reverse-Engineering & Documenting a Model

When you take over a Power BI model, the first question is always "where does this number come from?", and clicking through Desktop one measure at a time doesn't answer it. A model is a graph: measures read measures, which read columns, which come from source queries and warehouse tables. This chapter reads that graph from the model's definition with a script and generates a page for every measure: its DAX, everything it depends on, and the warehouse columns it finally reads. We run it on AdventureWorksPL; it works the same on a model you inherit.

The questions documentation must answer

  • Where does this number come from? From a measure, through other measures, down to model columns, the source query and the warehouse tables.
  • What breaks if I change this? Every measure that depends on the one being changed, directly or indirectly.
  • What can we delete? Measures nothing uses, columns no measure reads.
  • Is the logic consistent? The same rule written once, or copied twenty times with small differences?

Step 1: get the definition

Everything starts from the model as text:

  • A .pbix you have: open it in Power BI Desktop and save it as a PBIP project (Chapter 7). The TMDL folder is <name>.SemanticModel/definition.
  • A published model: connect Tabular Editor to the workspace's XMLA endpoint and save the model to a TMDL folder, or script it from SQL Server Management Studio.

No data is needed. The definition holds every table, column (with its sourceColumn and data type), measure, partition query, shared expression, relationship and role. That is all the script reads. Rather than parse TMDL text itself, it loads the folder with the Tabular Object Model library that ships with Power BI Desktop, so the objects come out exactly as the engine sees them.

Step 2: build the dependency graph

DAX has a simple convention that makes the next part possible: a measure is referenced as [Name], a column as Table[Name] or 'Table Name'[Name]. So for each measure:

  1. Remove comments and string literals, so a bracket inside "text [like this]" or -- rate differs per row isn't read as a reference.
  2. Table-qualified brackets are column references, if that column exists. (Table[Measure] is legal DAX too, so check measures as well.)
  3. Bare brackets not preceded by a table name are measure references, if a measure of that name exists.
  4. Walk the graph level by level: level 1 is what the measure references directly, level 2 what those reference, and so on, until only columns remain.

Step 3: trace columns to the warehouse

Each model column has a sourceColumn: its name at the end of the table's query. To get further, the script reads the table's partition query, including any shared expression it uses (the Sales partitions read SalesSource; Date reads FiscalCalendarSql):

  • FROM and JOIN clauses give the warehouse tables the query reads.
  • The line <expression> AS <sourceColumn> gives the SQL expression behind the column, such as CAST(s.DiscountAmount AS decimal(19, 4)). This is one more reason to name columns in SQL rather than rename them in Power Query: the alias is the lineage.

If your warehouse has its own lineage (view definitions, a dbt manifest, a SQL lineage tool), join it on from here to continue past the warehouse tables to staging and source systems.

Step 4: generate the documentation

The script below writes one Markdown page per measure and a catalogue. It needs only PowerShell and Power BI Desktop. It is bi/code/tools/document_model.ps1 in the repository:

<#
.SYNOPSIS
    Documents every measure in a Power BI semantic model saved as TMDL: DAX, dependencies and source lineage.

.EXAMPLE
    .\document_model.ps1 -Definition ..\AdventureWorksPL\AdventureWorksPL.SemanticModel\definition -Out ..\model_docs

.NOTES
    Reads the model with the Tabular Object Model that ships with Power BI Desktop, so it runs anywhere Desktop is installed.
#>
param(
    [Parameter(Mandatory)] [string]$Definition,
    [string]$Out = 'model_docs',
    [string]$TomDll = 'C:\Program Files\Microsoft Power BI Desktop\bin\Microsoft.PowerBI.Tabular.dll'
)

Add-Type -Path $TomDll
$model = [Microsoft.AnalysisServices.Tabular.TmdlSerializer]::DeserializeDatabaseFromFolder((Resolve-Path $Definition)).Model

$daxNoise  = '(?s)//[^\n]*|--[^\n]*|/\*.*?\*/|"(?:[^"]|"")*"'          # comments and string literals
$bareRef   = "(?<!['\w\]])\[([^\]]+)\]"                                   # [Measure]
$colRef    = "'([^']+)'\[([^\]]+)\]|\b([A-Za-z_]\w*)\[([^\]]+)\]"          # Table[Column]
$sqlTables = '(?i)\b(?:FROM|JOIN)\s+(dbo\.\w+)'                           # warehouse tables in a source query

# --- load: measures, columns, and where each table's data comes from ------------------------------
$shared = @{}
foreach ($e in $model.Expressions) { $shared[$e.Name] = $e.Expression }

function Get-SourceText([string]$m) {
    # A partition query plus every shared expression it uses (SalesSource, FiscalCalendarSql, ...).
    $text = $m
    foreach ($name in $shared.Keys) { if ($m -match "\b$([regex]::Escape($name))\b") { $text += "`n" + (Get-SourceText $shared[$name]) } }
    $text
}

$measures = [ordered]@{}; $columns = @{}; $sources = @{}
foreach ($t in $model.Tables) {
    $src = ($t.Partitions | Where-Object { $_.Source -is [Microsoft.AnalysisServices.Tabular.MPartitionSource] } |
            ForEach-Object { Get-SourceText $_.Source.Expression }) -join "`n"
    $sources[$t.Name] = (([regex]::Matches($src, $sqlTables) | ForEach-Object { $_.Groups[1].Value }) | Sort-Object -Unique) -join ', '
    foreach ($c in $t.Columns) {
        if ($c.Type -eq 'RowNumber') { continue }
        # the SQL expression that produces the column: "<expression> AS <name>" in the source query
        $alias = [regex]::Escape($c.SourceColumn)
        $hit = [regex]::Match($src, "(?im)^\s*,?\s*(.+?)\s+AS\s+(?:\[$alias\]|$alias)\s*,?\s*(?:/\*.*\*/|--.*)?$")
        $columns["$($t.Name)|$($c.Name)"] = if ($hit.Success) { $hit.Groups[1].Value.Trim() -replace '\s+', ' ' } else { $c.SourceColumn }
    }
    foreach ($m in $t.Measures) {
        $measures[$m.Name] = [pscustomobject]@{ Table = $t.Name; Dax = $m.Expression.Trim(); Folder = $m.DisplayFolder
                                                Description = $m.Description; Hidden = $m.IsHidden }
    }
}

# --- dependency graph -----------------------------------------------------------------------------
function Get-References([string]$dax) {
    $code = [regex]::Replace($dax, $daxNoise, ' ')
    $deps = [Collections.Generic.HashSet[string]]::new()
    $cols = [Collections.Generic.HashSet[string]]::new()
    foreach ($r in [regex]::Matches($code, $colRef)) {
        $table = if ($r.Groups[1].Success) { $r.Groups[1].Value } else { $r.Groups[3].Value }
        $name  = if ($r.Groups[2].Success) { $r.Groups[2].Value } else { $r.Groups[4].Value }
        if ($columns.ContainsKey("$table|$name")) { [void]$cols.Add("$table|$name") }
        elseif ($measures.Contains($name)) { [void]$deps.Add($name) }        # Table[Measure] is legal DAX too
    }
    foreach ($r in [regex]::Matches($code, $bareRef)) {
        if ($measures.Contains($r.Groups[1].Value)) { [void]$deps.Add($r.Groups[1].Value) }
    }
    , @($deps, $cols)
}

$graph = @{}; $usedBy = @{}
foreach ($name in $measures.Keys) { $graph[$name] = Get-References $measures[$name].Dax; $usedBy[$name] = @() }
foreach ($name in $measures.Keys) { foreach ($d in $graph[$name][0]) { $usedBy[$d] += $name } }

function Get-Levels([string]$name) {
    # measures that $name depends on, level by level (level 1 = direct)
    $seen = @{ $name = $true }; $levels = @(); $frontier = @($graph[$name][0])
    while ($frontier.Count) {
        $new = @($frontier | Where-Object { -not $seen.ContainsKey($_) } | Sort-Object -Unique)
        if (-not $new.Count) { break }
        $levels += , $new
        $new | ForEach-Object { $seen[$_] = $true }
        $frontier = @($new | ForEach-Object { $graph[$_][0] } | ForEach-Object { $_ })
    }
    , $levels
}

function Node([string]$label) { ($label -replace '\W+', '_') + '["' + ($label -replace '"', "'") + '"]' }

# --- write one page per measure and a catalogue ---------------------------------------------------
$docs = Join-Path $Out 'docs'
New-Item -ItemType Directory -Force $docs | Out-Null
$enc = New-Object System.Text.UTF8Encoding $false
$catalogue = @('# Measure catalogue', '',
               '| Measure | Folder | Direct measures | Direct columns | All source columns | Used by |',
               '|---|---|---|---|---|---|')

foreach ($name in $measures.Keys | Sort-Object) {
    $m = $measures[$name]; $levels = Get-Levels $name
    $chain = @($name) + @($levels | ForEach-Object { $_ })
    $allCols = @($chain | ForEach-Object { $graph[$_][1] } | ForEach-Object { $_ } | Sort-Object -Unique)

    $page = @("# $name", '',
              "- Home table: ``$($m.Table)``",
              "- Display folder: ``$(if ($m.Folder) { $m.Folder } else { '-' })``",
              "- Hidden: $($m.Hidden)",
              "- Used by: $(if ($usedBy[$name].Count) { ($usedBy[$name] | Sort-Object) -join ', ' } else { 'no other measure' })")
    if ($m.Description) { $page += @('', $m.Description) }
    $page += @('', '## DAX', '```dax', $m.Dax, '```', '', '## Depends on')
    if ($levels.Count) { for ($i = 0; $i -lt $levels.Count; $i++) { $page += "- Level $($i + 1): " + (($levels[$i] | ForEach-Object { "[$_]" }) -join ', ') } }
    else { $page += '- no other measures' }
    $page += @('', '## Source columns', '| Model column | Warehouse tables | Source expression |', '|---|---|---|')
    foreach ($c in $allCols) {
        $t, $col = $c -split '\|', 2
        $page += "| $t[$col] | $($sources[$t]) | ``$($columns[$c])`` |"
    }
    $page += @('', '## Lineage', '```mermaid', 'graph LR')
    foreach ($target in $chain) {
        foreach ($d in ($graph[$target][0] | Sort-Object)) { $page += "  $(Node $d) --> $(Node $target)" }
        foreach ($c in ($graph[$target][1] | Sort-Object)) { $t, $col = $c -split '\|', 2; $page += "  $(Node "$t[$col]") --> $(Node $target)" }
    }
    $page += '```'

    $file = ((($name -replace '%', 'pct') -replace '\W+', '_').Trim('_')) + '.md'    # "vs LY" and "vs LY %" must not collide
    [IO.File]::WriteAllText((Join-Path $docs $file), ($page -join "`n"), $enc)
    $catalogue += "| [$name](docs/$file) | $($m.Folder) | $($graph[$name][0].Count) | $($graph[$name][1].Count) | $($allCols.Count) | $($usedBy[$name].Count) |"
}

[IO.File]::WriteAllText((Join-Path $Out 'README.md'), ($catalogue -join "`n"), $enc)
Write-Output "$($measures.Count) measures documented in $((Resolve-Path $Out).Path)"

Run it against the PBIP folder and commit the output next to the model, or publish it as a static site. GitHub renders the Mermaid blocks as diagrams.

Limits of a regex parser

The script recognises DAX references and SQL aliases by pattern, not by fully parsing DAX or SQL. A variable named like a measure, an unusual quoting style or a column computed over several lines can fool it. For documentation and impact analysis that is good enough, and every page shows the DAX so a reader can check. If you need exact dependencies, the engine reports them: query INFO.CALCDEPENDENCY() in DAX query view or DAX Studio.

Exercise: impact of a change

You want to change how _Show Local Currency decides when to convert. How do you list every measure affected, using the script's data?

Answer

Walk $usedBy instead of the dependencies: start at _Show Local Currency, add every measure that uses it, then every measure that uses those, until nothing new appears. It is Get-Levels run on the reversed graph. The result is the list of measures to re-test after the change; in this model it is most of the P&L.

Key takeaways

  • Documentation of a model must be generated from its definition, not written by hand.
  • [Name] is a measure, Table[Name] a column: enough to build the dependency graph once comments and strings are removed.
  • Partition queries and their aliases map model columns to SQL expressions and warehouse tables.
  • The catalogue turns vague doubts into lists: dead measures, broken layers, copy-paste, unused columns. Run it on your own model too: it found a layer violation here.
