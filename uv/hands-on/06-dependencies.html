Dependencies in Depth

Real projects have more than a flat list of packages. Some are only for development, some are optional features, some come from git or a company index, and some differ by operating system. This chapter covers every kind, using the fuelprice project.

~35 min Commands: uv add · uv remove · uv tree · uv lock --upgrade-package Lab: fuelprice

Version specifiers

Everything you pass to uv add is a standard requirement string. Quote them in the shell, because < and > mean redirection there.

RequirementMeansWhen to use
httpxAny version (uv adds >= current)The normal case
"httpx>=0.27"0.27 or newerYou need a feature added in 0.27
"httpx>=0.27,<1"Lower and upper boundYou know 1.0 will break you
"pandas~=2.2"Compatible release: >=2.2,<3Trust minor releases, not major ones
"numpy==2.1.3"Exactly this versionRarely in pyproject.toml: the lockfile pins for you
"numpy!=2.1.0"Anything except a known-bad releaseSkipping a broken version
"httpx[http2]"Install the package's extra named http2Optional features of a library
"pywin32; sys_platform == 'win32'"Only on Windows (an environment marker)Platform-specific packages

Ranges in pyproject.toml, pins in the lockfile

Keep pyproject.toml loose (lower bounds, upper bounds only when you know of a break) and let uv.lock do the exact pinning. Tight pins in pyproject.toml make upgrades painful and, for libraries, cause conflicts for everyone who installs you.

Four kinds of dependency

Not every package is needed by everyone. pyproject.toml has separate places for each audience:

Development dependencies

Test runners, type checkers and linters are needed to work on the project, not to run it. Add them to the dev group:

$ uv add --dev pytest pytest-cov
$ uv add --group lint ruff mypy
$ uv add --group docs mkdocs-material
[dependency-groups]
dev  = ["pytest>=8.4", "pytest-cov>=6.2"]
lint = ["ruff>=0.12", "mypy>=1.17"]
docs = ["mkdocs-material>=9.6"]

[dependency-groups] is a Python standard (PEP 735). By default uv sync and uv run install the dev group but not the others. Control it per command or per project:

$ uv sync --group lint              # dev + lint
$ uv sync --all-groups              # every group
$ uv sync --no-dev                  # production: no dev group
$ uv sync --only-group lint         # just the lint group, not even the project
$ uv run --group docs mkdocs serve
[tool.uv]
default-groups = ["dev", "lint"]

Optional extras

Extras are optional features for users. If fuelprice could draw charts, people who don't want charts shouldn't have to install matplotlib:

$ uv add --optional plot matplotlib
$ uv sync --extra plot                 # include it locally
$ uv sync --all-extras
[project.optional-dependencies]
plot = ["matplotlib>=3.10"]

Inside your code, import matplotlib only where charts are drawn, and show a friendly message if it's missing.

Where packages come from: sources

By default every package comes from PyPI. [tool.uv.sources] lets you take a package from somewhere else during development, without changing the standard dependency list:

$ uv add git+https://github.com/encode/httpx --tag 0.28.1      # a git tag
$ uv add git+https://github.com/you/pricetools --branch main     # a branch
$ uv add ../shared-utils --editable                              # a local folder
[project]
dependencies = ["httpx", "pricetools", "shared-utils"]

[tool.uv.sources]
httpx        = { git = "https://github.com/encode/httpx", tag = "0.28.1" }
pricetools   = { git = "https://github.com/you/pricetools", branch = "main" }
shared-utils = { path = "../shared-utils", editable = true }

Editable means your .venv points at the folder instead of a copy, so changes to shared-utils are visible immediately, without reinstalling. The lockfile records the exact git commit for git sources, so a branch is still reproducible.

Sources are a uv feature

[tool.uv.sources] is used by uv only. When your package is built and published, the dependency stays a plain pricetools requirement resolved from PyPI. That's what you want for libraries; for applications that are never published it makes no difference.

Package indexes

An index is a server that hosts packages, such as PyPI, a company Artifactory or Nexus, or PyTorch's own index. Define extra indexes in pyproject.toml:

[[tool.uv.index]]
name = "pytorch-cpu"
url = "https://download.pytorch.org/whl/cpu"
explicit = true                       # only for packages that ask for it

[tool.uv.sources]
torch = { index = "pytorch-cpu" }
[[tool.uv.index]]
name = "company"
url = "https://pypi.company.example/simple"
default = true                        # replaces PyPI completely

Credentials never go into pyproject.toml. Pass them as environment variables named after the index:

$ export UV_INDEX_COMPANY_USERNAME=sameera
$ export UV_INDEX_COMPANY_PASSWORD=…           # a token from your secret store
$ uv sync

Under the hood: why uv won't mix indexes

pip, given several indexes, picks the best version of a package from any of them. That allows a dependency confusion attack: someone uploads a package to PyPI with the same name as your internal one and a higher version number, and pip installs theirs. uv's default (index-strategy = "first-index") takes a package only from the first index that has it, in the order you defined them. Leave that default in place unless you have a very good reason.

$ uv tree --depth 1               # only direct dependencies
$ uv tree --invert --package idna # who needs idna?
$ uv tree --outdated              # show where newer versions exist

Upgrading safely

uv never upgrades a locked package on its own. uv add and uv sync keep the versions in uv.lock unless they no longer satisfy pyproject.toml. Upgrades are always a deliberate step:

$ uv lock --upgrade-package httpx            # one package (and what it needs)
$ uv lock --upgrade-package "httpx<0.29"     # one package, up to a limit
$ uv lock --upgrade                          # everything, within your ranges
$ uv sync                                    # install the new lock

A good routine: upgrade on a branch, run the tests, and review the uv.lock diff in the pull request. The diff shows exactly which versions changed.

To raise the lower bound in pyproject.toml as well (for example because you now use a new feature), add the package again with the new requirement: uv add "httpx>=0.28".

Try it yourself

Exercise

  1. In fuelprice, add pytest to the dev group and ruff to a lint group.
  2. Add matplotlib as a plot extra. Run uv sync, then uv sync --extra plot, and compare what was installed and removed.

  4. Run uv sync --no-dev. Is pytest still in .venv?

Key takeaways

  • Write ranges in pyproject.toml; let uv.lock pin exact versions.
  • Main dependencies are for everyone, extras are optional features for users, dependency groups are for developers only.
  • [tool.uv.sources] takes packages from git, local folders or a named index; credentials go in UV_INDEX_<NAME>_* variables.
  • uv takes a package from the first index that has it, which protects you from dependency confusion.
  • Upgrades are explicit: uv lock --upgrade-package or --upgrade, then review the lockfile diff.
