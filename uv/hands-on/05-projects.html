Your First Project

A script is one file. A project is a folder with a pyproject.toml: it can have many modules, tests, a lockfile and a command-line entry point. In this chapter you build fuelprice, a small app you'll keep extending until the end of the tutorial.

~30 min Commands: uv init · uv add · uv remove · uv run · uv sync Lab: fuelprice

Step 1: Create the project

$ uv init fuelprice
Initialized project `fuelprice` at `/home/sameera/fuelprice`

$ cd fuelprice
$ ls -a
.  ..  .git  .gitignore  .python-version  README.md  main.py  pyproject.toml

uv created a git repository and five files:

FilePurpose
pyproject.tomlThe project definition: name, version, Python range and dependencies
.python-versionThe Python version for this folder (Chapter 3)
main.pyA "hello world" to start from
README.mdEmpty project description
.gitignoreAlready ignores .venv, __pycache__ and build output
 
[project]
name = "fuelprice"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
requires-python = ">=3.12"
dependencies = []

requires-python is important: it says which Python versions the project supports, and uv resolves dependencies so they work on all of them.

Step 2: Run it

$ uv run main.py
Using CPython 3.12.11
Creating virtual environment at: .venv
Hello from fuelprice!

The first uv run did three things you didn't ask for: chose a Python, created .venv, and wrote uv.lock. Look:

$ ls -a
.  ..  .git  .gitignore  .python-version  .venv  README.md  main.py  pyproject.toml  uv.lock

That's the mental model from Chapter 1 in action: uv run keeps pyproject.toml, uv.lock and .venv in step before running your command.

Step 3: Add dependencies

$ uv add httpx rich
Resolved 12 packages in 180ms
Prepared 11 packages in 95ms
Installed 11 packages in 14ms

 + certifi==2026.x
 + httpx==0.28.1
 + rich==14.x
 …

One command updated all three places:

dependencies = [
    "httpx>=0.28.1",
    "rich>=14.0.0",
]

uv wrote a lower bound (>=) at the version it just installed. That's a sensible default: your code is known to work with that version, and newer compatible versions are still allowed. The exact versions are recorded in uv.lock.

Now write the app. Replace main.py:

import csv
from pathlib import Path

from rich.console import Console
from rich.table import Table

def load(path: Path) -> list[dict]:
    with path.open(newline="") as f:
        return list(csv.DictReader(f))

def main() -> None:
    rows = load(Path("prices.csv"))
    table = Table(title="Fuel prices (Rs. per litre)")
    for col in ("month", "petrol_92", "petrol_95"):
        table.add_column(col, justify="right")
    for r in rows:
        table.add_row(r["month"], r["petrol_92"], r["petrol_95"])
    Console().print(table)

if __name__ == "__main__":
    main()

2026-09,305,365
2026-10,311,372
$ uv run main.py

Removing a dependency is the mirror image: uv remove httpx takes it out of pyproject.toml, re-locks and uninstalls it from .venv.

Step 4: Turn it into a real command

The project so far is an application: code you run from its folder. To get a proper fuelprice command, with code you can import and later publish, use the packaged layout. Start a fresh project with --package to see the difference:

$ cd ..
$ uv init --package fuelprice-pkg
$ tree fuelprice-pkg
fuelprice-pkg
├── .python-version
├── README.md
├── pyproject.toml
└── src
    └── fuelprice_pkg
        └── __init__.py
[project]
name = "fuelprice-pkg"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = []

[project.scripts]
fuelprice-pkg = "fuelprice_pkg:main"     # command name = "module:function"

[build-system]
requires = ["uv_build"]                  # uv init writes a version range here
build-backend = "uv_build"

Two new sections appear. [project.scripts] creates a command in .venv/bin (.venv\Scripts on Windows) that calls main(). [build-system] tells uv how to build the project into a wheel, and because there's a build system, uv installs your own project into .venv as an editable package, so imports work from anywhere.

$ cd fuelprice-pkg
$ uv run fuelprice-pkg
Hello from fuelprice-pkg!

Application, package or library?

CommandLayoutBuild systemUse it for
uv init (or --app)main.py in the rootNoScripts, notebooks, web apps, data pipelines you run in place
uv init --packagesrc/<name>/YesCommand-line tools; anything you'll install elsewhere
uv init --libsrc/<name>/ + py.typedYesLibraries other projects import, usually published to PyPI

Step 5: Clone and go

This is where uv projects shine. A colleague clones your repository and runs one command:

$ git clone https://github.com/you/fuelprice.git
$ cd fuelprice
$ uv sync
Using CPython 3.12.11
Creating virtual environment at: .venv
Resolved 12 packages in 3ms
Installed 11 packages in 20ms

They get the same Python minor version and exactly the same package versions as you, on Windows, macOS or Linux. They could even skip uv sync: the first uv run does it automatically.

To activate or not to activate?

With uv you don't need to activate the virtual environment: uv run <command> always uses the project's .venv. But activation still works if you prefer typing plain python and pytest:

$ source .venv/bin/activate          # macOS and Linux
PS> .venv\Scripts\activate           # Windows PowerShell
(fuelprice) $ python main.py
(fuelprice) $ deactivate

An activated environment doesn't sync

Plain python in an activated environment won't check whether .venv matches uv.lock. After pulling changes from git, run uv sync or use uv run, which syncs automatically.

Editors

VS Code, PyCharm and most editors detect .venv in the project root automatically. If not, choose the interpreter at .venv/bin/python (or .venv\Scripts\python.exe on Windows). In VS Code: Python: Select Interpreter.

Try it yourself

Exercise

  1. Move the fuelprice code from main.py into fuelprice-pkg/src/fuelprice_pkg/__init__.py and add rich with uv add.
  2. Run it as a command with uv run fuelprice-pkg.
  3. Delete .venv completely, then run the command again. How long did the rebuild take?

Key takeaways

  • uv init creates an application; --package adds a src/ layout, a build system and a command entry point; --lib is for importable libraries.
  • uv add and uv remove update pyproject.toml, uv.lock and .venv in one step.
  • uv run always runs in an up-to-date .venv, so activation is optional.
  • Commit pyproject.toml, uv.lock and .python-version; a clone plus uv sync reproduces your environment exactly.
