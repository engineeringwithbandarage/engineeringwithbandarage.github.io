Chapter 04 · Beginner

Scripts with Inline Dependencies

Not everything needs to be a project. A one-file script that cleans a CSV or calls an API is often all you need. The classic problem is sharing it: "first install pandas and requests, then…". With uv, a script carries its own dependency list inside the file, and uv run script.py does the rest.

~25 min Commands: uv run · uv init --script · uv add --script · uv lock --script Standard: PEP 723 inline script metadata

Step 1: A script with no dependencies

Create a folder for this chapter and a file called prices.py:

prices = {"2026-08": 299, "2026-09": 305, "2026-10": 311}

for month, price in prices.items():
    print(f"{month}: Rs. {price}")

change = (prices["2026-10"] - prices["2026-08"]) / prices["2026-08"]
print(f"Change over the period: {change:.1%}")
$ uv run prices.py
2026-08: Rs. 299
2026-09: Rs. 305
2026-10: Rs. 311
Change over the period: 4.0%

So far this is just python prices.py, except uv found (or downloaded) a Python for you.

Step 2: Add a dependency for one run

Let's print a proper table with the rich library. Change the script:

from rich.console import Console
from rich.table import Table

prices = {"2026-08": 299, "2026-09": 305, "2026-10": 311}

table = Table(title="Petrol 92 (Rs. per litre)")
table.add_column("Month")
table.add_column("Price", justify="right")
for month, price in prices.items():
    table.add_row(month, str(price))

Console().print(table)
$ uv run prices.py
ModuleNotFoundError: No module named 'rich'

$ uv run --with rich prices.py
Installed 4 packages in 9ms
   Petrol 92 (Rs. per litre)
┏━━━━━━━━━┳━━━━━━━┓
┃ Month   ┃ Price ┃
┡━━━━━━━━━╇━━━━━━━┩
│ 2026-08 │   299 │
│ 2026-09 │   305 │
│ 2026-10 │   311 │
└─────────┴───────┘

--with works, but you have to remember it every time, and so does everyone you share the script with. Better to write the dependency into the script.

Step 3: Declare dependencies inside the script

Python has a standard for this, PEP 723 inline script metadata: a specially formatted comment block at the top of the file. Let uv write it for you:

$ uv add --script prices.py rich
Updated `prices.py`

The top of prices.py now looks like this:

# /// script
# requires-python = ">=3.12"
# dependencies = [
#     "rich",
# ]
# ///

from rich.console import Console
…
$ uv run prices.py          # no --with needed any more
Installed 4 packages in 8ms
   Petrol 92 (Rs. per litre)
…

The block is ordinary comments, so plain Python ignores it. uv (and other tools that support PEP 723, such as pipx and Hatch) read it, build an environment that matches and run the script there.

Step 4: Start a new script the uv way

uv init --script creates a file with the metadata block already in place:

$ uv init --script fetch_rates.py --python 3.12
$ uv add --script fetch_rates.py "httpx>=0.27" rich
# /// script
# requires-python = ">=3.12"
# dependencies = [
#     "httpx>=0.27",
#     "rich",
# ]
# ///
import httpx
from rich import print

resp = httpx.get("https://pypi.org/pypi/uv/json", timeout=10)
resp.raise_for_status()
print(f"Latest uv on PyPI: [bold]{resp.json()['info']['version']}[/]")
$ uv run fetch_rates.py
Latest uv on PyPI: X.Y.Z

Step 5: Make a script run like a program

On macOS and Linux, a shebang line lets you run the script directly, and uv takes care of the dependencies:

#!/usr/bin/env -S uv run --script
# /// script
# dependencies = ["rich"]
# ///
…
$ chmod +x prices.py
$ ./prices.py

On Windows, run it with uv run prices.py; the shebang line is ignored there.

Step 6: Make a script reproducible

"rich" without a version means "the latest", which changes over time. There are two ways to freeze a script in time.

Option A: exclude-newer

Tell uv to ignore any release published after a date. Every run then resolves to the versions that were current on that day:

# /// script
# requires-python = ">=3.12"
# dependencies = ["rich"]
# [tool.uv]
# exclude-newer = "2026-10-31T00:00:00Z"
# ///

Option B: a lockfile next to the script

$ uv lock --script prices.py
$ ls
prices.py  prices.py.lock

Once prices.py.lock exists, uv run prices.py installs exactly the versions in it. Share both files together. Chapter 7 explains what is inside a lockfile.

Quick experiments without a file

$ uv run --with pandas python                         # a REPL with pandas
$ uv run --with "pandas<2" --python 3.11 python       # an older pandas on 3.11
$ uv run --with jupyter jupyter lab                    # throw-away notebook server
$ echo 'print("hi")' | uv run -                        # read the script from stdin

Scripts inside a project

If you run uv run something.py inside a uv project folder (one with a pyproject.toml), uv runs it in the project's environment, unless the script has its own metadata block, in which case the block wins. Use uv run --no-project something.py to ignore the project explicitly.

Try it yourself

Exercise

  1. Write a script that uses pandas to read a small CSV of monthly prices and print the average.
  2. Add the dependency with uv add --script and run it with uv run.
  3. Lock it with uv lock --script, then send both files to a colleague (or another machine) and run it there.

Key takeaways

  • uv run script.py runs a script; --with adds packages for a single run.
  • The PEP 723 # /// script block puts the dependency list inside the file. Manage it with uv add --script.
  • uv builds and caches the script's environment for you, so there's nothing to create or activate.
  • Freeze a script with exclude-newer or a .lock file from uv lock --script.
