Command-Line Tools with uvx

Many Python packages are really programs: Ruff, Black, pytest, httpie, dbt, pre-commit, the AWS CLI. Installing them globally with pip mixes their dependencies together until something breaks. uv runs each tool in its own isolated environment, either on demand with uvx or installed permanently with uv tool install.

~20 min Commands: uvx · uv tool install · list · upgrade · uninstall Replaces: pipx

Run a tool once: uvx

uvx is short for uv tool run. It creates a temporary, cached environment for the tool, runs it and leaves nothing behind on your PATH.

$ uvx ruff check .                  # lint the current folder
$ uvx ruff format .                 # format it
$ uvx pycowsay "hello"
$ uvx --python 3.12 ipython         # a REPL on a specific Python

The first run downloads the tool; later runs start almost instantly from the cache.

When the command and package names differ

uvx assumes the command has the same name as the package. When it doesn't, say which package provides it with --from:

$ uvx --from httpie http https://pypi.org/pypi/uv/json     # package httpie, command http
$ uvx --from dbt-postgres dbt --version                     # package dbt-postgres, command dbt
$ uvx --from "huggingface_hub[cli]" huggingface-cli --help  # with an extra

Choose the version

$ uvx ruff@0.12.0 check .             # exactly 0.12.0
$ uvx ruff@latest check .             # check for the newest release now
$ uvx --from "ruff>=0.11,<0.13" ruff check .

Add plug-ins

Some tools load plug-ins that must be installed next to them. --with adds packages to the tool's environment:

$ uvx --with mkdocs-material mkdocs serve
$ uvx --with pandas --with matplotlib jupyter lab

Install a tool permanently

For tools you use every day, install them once. The command is then on your PATH, like any other program:

$ uv tool install ruff
Resolved 1 package in 120ms
Installed 1 package in 6ms
 + ruff==0.12.x
Installed 1 executable: ruff

$ ruff --version
ruff 0.12.x
$ uv tool list                       # what's installed, with executables
$ uv tool upgrade ruff               # upgrade one tool
$ uv tool upgrade --all              # upgrade everything
$ uv tool install "dbt-core<1.11" --with dbt-postgres   # pin + plug-in
$ uv tool install --python 3.12 httpie                 # choose its Python
$ uv tool install -e ./my-cli        # your own tool, editable from a folder
$ uv tool uninstall ruff

"warning: … is not on your PATH"

Tools are installed into uv's executable folder (uv tool dir --bin). If the installer didn't add it to your PATH, run uv tool update-shell once and open a new terminal.

Tool or dev dependency?

Ruff can be installed as a tool or added to a project's dev group. Which is right?

uvx / uv tool installuv add --dev
VersionWhatever you installed; differs per personLocked in uv.lock; same for the whole team and CI
Sees your project's packagesNo (isolated)Yes (same .venv)
Good forGeneral utilities: httpie, pre-commit, cookiecutter, the AWS CLIpytest, mypy, project linters: anything whose result must be identical for everyone

The rule of thumb: if the tool needs to import your code (pytest, mypy, pylint) or CI depends on its exact version, make it a dev dependency and run it with uv run. Otherwise, a tool is fine.

$ uv run pytest          # pytest from the project's dev group: sees fuelprice
$ uvx pytest             # an isolated pytest: can't import fuelprice's dependencies

Key takeaways

  • uvx <tool> runs a tool in a cached, isolated environment without installing it.
  • --from names the package when the command name differs; tool@version pins it; --with adds plug-ins.
  • uv tool install puts a tool on your PATH permanently, still isolated from everything else.
  • Tools that import your code or must match CI exactly belong in the project's dev group instead.
