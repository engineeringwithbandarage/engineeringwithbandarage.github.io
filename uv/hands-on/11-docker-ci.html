uv in Docker and CI/CD

The lockfile pays off most in automation: every CI run and every container image gets exactly the versions you tested. This chapter builds a production Docker image for priceapi that rebuilds in seconds when only code changes, and a GitHub Actions pipeline that tests, checks the lock and publishes.

~45 min Docker BuildKit · GitHub Actions Lab: fuelprice priceapi

Part 1: Docker

Getting uv into an image

Astral publishes uv as a container image. The cleanest way to get it is to copy the two binaries from it, pinned to a version:

COPY --from=ghcr.io/astral-sh/uv:0.9 /uv /uvx /bin/

Pin a version (as here) or even a digest, so a new uv release can never change your build unexpectedly. There are also ready-made images with uv and Python together, such as ghcr.io/astral-sh/uv:python3.12-bookworm-slim.

The key idea: dependencies in their own layer

Docker caches each instruction as a layer and reuses it if its inputs haven't changed. Dependencies change rarely; your code changes on every commit. So install dependencies first, from only the lockfile and pyproject.toml, and copy the code afterwards:

A production Dockerfile

# ---------- build stage: has uv, builds the virtual environment ----------
FROM python:3.12-slim AS builder
COPY --from=ghcr.io/astral-sh/uv:0.9 /uv /uvx /bin/

ENV UV_COMPILE_BYTECODE=1 \
    UV_LINK_MODE=copy \
    UV_PYTHON_DOWNLOADS=never

WORKDIR /app

# 1) Dependencies only: cached until uv.lock or pyproject.toml change
RUN --mount=type=cache,target=/root/.cache/uv \
    --mount=type=bind,source=uv.lock,target=uv.lock \
    --mount=type=bind,source=pyproject.toml,target=pyproject.toml \
    uv sync --locked --no-install-project --no-dev

# 2) The project itself
COPY . /app
RUN --mount=type=cache,target=/root/.cache/uv \
    uv sync --locked --no-dev --no-editable

# ---------- runtime stage: no uv, no build tools, just the venv ----------
FROM python:3.12-slim
RUN useradd --create-home app
COPY --from=builder --chown=app:app /app/.venv /app/.venv
ENV PATH="/app/.venv/bin:$PATH"
USER app
EXPOSE 8000
CMD ["uvicorn", "priceapi.main:app", "--host", "0.0.0.0", "--port", "8000"]
LineWhy
UV_COMPILE_BYTECODE=1Compile .pyc files at build time, so the container starts faster.
UV_LINK_MODE=copyThe cache mount is a different filesystem, so hard links aren't possible; this silences the warning.
UV_PYTHON_DOWNLOADS=neverUse the image's Python; never download another one by surprise.
--mount=type=cacheKeeps uv's cache between builds without putting it in the image.
--mount=type=bindMakes the two files visible to that one step without a COPY layer.
--lockedFail the build if the lock is stale instead of silently re-resolving.
--no-install-projectInstall dependencies only; the code isn't there yet.
--no-editableInstall your project as a normal package, so the runtime stage needs only .venv, not the source folder.
Two stagesThe final image contains Python and the environment, but not uv, caches or build tools.

Add a .dockerignore, or your local .venv gets copied in and overwrites the one built in the image:

.venv
__pycache__
.git
dist

In a workspace

For a workspace member, build from the workspace root (so uv.lock is in the context) and select the member: uv sync --locked --no-dev --package priceapi. Use --frozen in the dependencies step if the member pyproject.toml files aren't mounted yet, because uv can't check the lock against files it can't see.

$ docker build -t priceapi .
$ docker run --rm -p 8000:8000 priceapi
# change one line of code and rebuild: only the last layers run
$ docker build -t priceapi .

Part 2: GitHub Actions

Astral's setup-uv action installs uv and caches its downloads between runs.

name: CI
on:
  push:
    branches: [main]
  pull_request:

jobs:
  test:
    runs-on: ${{ matrix.os }}
    strategy:
      matrix:
        os: [ubuntu-latest, windows-latest, macos-latest]
        python: ["3.12", "3.13"]
    steps:
      - uses: actions/checkout@v4

      - uses: astral-sh/setup-uv@v6        # check for the latest major version
        with:
          enable-cache: true
          python-version: ${{ matrix.python }}

      - name: Lock is up to date
        run: uv lock --check

      - name: Install
        run: uv sync --locked --all-extras --dev

      - name: Lint
        run: uv run ruff check .

      - name: Test
        run: uv run pytest --cov

Setting python-version on the action exports UV_PYTHON, so every uv command in the job uses that version. One lockfile serves all six combinations in the matrix: that's universal resolution from Chapter 7 at work.

Publishing from CI with trusted publishing

name: Release
on:
  push:
    tags: ["pricecore-v*"]

jobs:
  publish:
    runs-on: ubuntu-latest
    environment: pypi
    permissions:
      id-token: write          # lets PyPI verify this workflow; no token needed
      contents: read
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
      - run: uv build --package pricecore
      - run: uv run --isolated --no-project --with dist/*.whl python -c "import pricecore"
      - run: uv publish

Other CI systems

Everything above works anywhere: install uv with the standalone installer (or the Docker image), cache the folder from uv cache dir keyed on a hash of uv.lock, and run the same uv commands. Before saving the cache, run uv cache prune --ci: it removes downloaded wheels that are quick to fetch again and keeps the ones that were built from source, which are slow to rebuild.

test:
  image: ghcr.io/astral-sh/uv:python3.12-bookworm-slim
  variables:
    UV_CACHE_DIR: .uv-cache
  cache:
    key:
      files: [uv.lock]
    paths: [.uv-cache]
  script:
    - uv sync --locked
    - uv run pytest
    - uv cache prune --ci

Key takeaways

  • Copy pinned uv binaries from ghcr.io/astral-sh/uv; install dependencies in their own layer with uv sync --locked --no-install-project, then copy the code.
  • Use BuildKit cache mounts with UV_LINK_MODE=copy, and UV_COMPILE_BYTECODE=1 for faster start-up.
  • Multi-stage builds ship only the .venv; --no-editable makes it independent of the source folder.
  • In CI: setup-uv with caching, uv lock --check, uv sync --locked, then uv run. Publish with trusted publishing, not stored tokens.
