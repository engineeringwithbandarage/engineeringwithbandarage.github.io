Workload Management

Lab:Ubuntu 24.04 VM on AWS+Docker · docker-compose+SQL Server 2022 on Linux (container)+Airflow 2.7 (containers)Resource Governor works the same on SQL Server for Linux as on Windows. Here it shares out the 2 vCPUs and the container's 2 GB memory cap between the ETL and everyone else.

A warehouse server runs two kinds of work: big batch loads and interactive report queries. Without limits, one ETL query with a huge memory grant can make every dashboard wait. The course's Chapter 5 solves this in Azure Synapse with a workload classifier. On SQL Server 2022 the same job is done by Resource Governor, and this chapter shows it working on the lab.

How classification works

  1. A session connects. An Airflow task opens an ODBC connection from the worker container to mssql:1433 as DataLoader.
  2. The classifier runs. SQL Server calls the one classifier function in master; it returns DataLoads for DataLoader and default for everyone else.
  3. Limits apply for the life of the session. Every query of that task runs with the group's importance, memory-grant cap and MAXDOP, inside the pool's CPU and memory share.

The setup script

-- Resource Governor: a pool and workload group for data loads
USE master;
GO

IF NOT EXISTS (SELECT * FROM sys.resource_governor_resource_pools WHERE name = 'DataLoadPool')
    CREATE RESOURCE POOL DataLoadPool
        WITH (MIN_CPU_PERCENT = 0, MAX_CPU_PERCENT = 80, MIN_MEMORY_PERCENT = 0, MAX_MEMORY_PERCENT = 60);
GO

IF NOT EXISTS (SELECT * FROM sys.resource_governor_workload_groups WHERE name = 'DataLoads')
    CREATE WORKLOAD GROUP DataLoads
        WITH (IMPORTANCE = HIGH, REQUEST_MAX_MEMORY_GRANT_PERCENT = 50, MAX_DOP = 2)
        USING DataLoadPool;
GO

-- An active classifier function can't be altered, so detach it first on a re-run
IF EXISTS (SELECT * FROM sys.resource_governor_configuration
           WHERE classifier_function_id = OBJECT_ID('master.dbo.fn_SBEcoLTDClassifier'))
BEGIN
    ALTER RESOURCE GOVERNOR WITH (CLASSIFIER_FUNCTION = NULL);
    ALTER RESOURCE GOVERNOR RECONFIGURE;
END
GO

-- Classifier: sessions of the DataLoader login go to DataLoads, everything else to default
CREATE OR ALTER FUNCTION dbo.fn_SBEcoLTDClassifier()
RETURNS sysname
WITH SCHEMABINDING
AS
BEGIN
    DECLARE @group sysname = N'default';
    IF SUSER_SNAME() = N'DataLoader'
        SET @group = N'DataLoads';
    RETURN @group;
END;
GO

ALTER RESOURCE GOVERNOR WITH (CLASSIFIER_FUNCTION = dbo.fn_SBEcoLTDClassifier);
ALTER RESOURCE GOVERNOR RECONFIGURE;
GO

SELECT is_enabled, OBJECT_NAME(classifier_function_id) AS classifier_function
FROM sys.resource_governor_configuration;

Proof it works

Every pipeline step records its own session's group in audit.StepLog, and the Resource Governor DMV counts requests and CPU per group:

TaskID                          | LoginName  | WorkloadGroupID
extract.extract_customers       | DataLoader | 256
facts.load_fact_orders          | DataLoader | 256
post_load.maintain_columnstore  | DataLoader | 256

name      | total_request_count | total_cpu_usage_ms | max_request_grant_memory_kb
default   | 4143                | 39502              | 106312
DataLoads | 2916                | 356932             | 300616

Since Resource Governor was configured, DataLoads did 90% of the CPU work in 41% of the requests, and the largest memory grant (300 MB) went to one of its requests, within its 50% per-request cap. That's the batch load, kept apart from the default group that interactive users share.

The classifier is server-wide

There is one classifier function for the whole instance, and it runs on every login, including the other labs' connections to this container. Keep it tiny and deterministic (no table lookups that can block), and remember that changing it needs ALTER RESOURCE GOVERNOR WITH (CLASSIFIER_FUNCTION = NULL) first. The build script does exactly that on a re-run.

Adding a group for report users

Extend the classifier with one more branch, for example IF IS_MEMBER('rpt_reader') = 1 RETURN 'Reports', with a modest REQUEST_MAX_MEMORY_GRANT_PERCENT (Chapter 13). Then neither side can starve the other.

Key takeaways

  • Synapse workload classifiers map to Resource Governor pools, groups and a classifier function.
  • Classification is by login, once per session, so give the ETL its own login.
  • The audit log proves which group each step ran in; the DMV shows the share each group used.
  • The classifier is instance-wide: keep it small, and detach it before changing it.
