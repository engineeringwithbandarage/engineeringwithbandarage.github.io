End-to-End Data Warehouse on Linux + Docker: SQL Server 2022 + Airflow

Lab:Ubuntu 24.04 VM on AWS+Docker · docker-compose+SQL Server 2022 on Linux (container)+Airflow 2.7 (containers)Every chapter, script and number in this tutorial comes from this Linux + Docker lab. There is no Windows server anywhere in it.

You will build SBEcoLTDDW, a sales data warehouse, from an operational database all the way to reporting views. SQL Server 2022, running in a Docker container on an Ubuntu Linux VM in AWS, stores and transforms the data. Apache Airflow, also in Docker containers on the same VM, only decides what runs when: every task is one SQL file kept in its own folder, so you can read, test and change the SQL without touching Python.

For: data engineers, BI developers, SQL developers Prerequisite: basic SQL ~4 hours

Infrastructure: Linux + Docker + SQL Server on Linux

The lab is one Ubuntu Linux virtual machine deployed in AWS. Docker runs every service in a container: SQL Server 2022 for Linux in one, Apache Airflow in six more. Your PC only edits files, opens SSH sessions and a browser.

Deployment: from the PC into the containers

Nothing is installed by hand inside a container. Files are edited on the PC, copied to the Linux server, and reach the containers either through bind mounts (Airflow) or through docker exec / docker cp (SQL Server).

  1. Copy the lab to the Linux server. scp puts the master copy from the PC into ~/sbecoltddw; shell scripts get their line endings converted to LF.
  2. Build the warehouse objects. run_sbecoltddw.sh pipes each course SQL file into sqlcmd inside the SQL Server Linux container with docker exec. There is no SQL Server client installed on the host.
  3. Reset the source when replaying. reset_source.sh pipes SQL into sqlcmd inside the container to undo the simulator's changes in AdventureWorks2022, so the scenarios of Chapter 12 can be run again from the original data.
  4. Install the pipeline into Airflow. setup_airflow_sbecoltddw.sh installs compose Version11, copies DAGs, plugin and SQL into ~/airflow, recreates the Airflow containers once, and creates the connection.
  5. Bind mounts make them live. The containers see ~/airflow/{dags,plugins,sql} as /opt/airflow/…; the scheduler picks up the DAGs within seconds.
  6. Run. Every task opens an ODBC connection from the Airflow worker container to mssql:1433 and runs one SQL file in SBEcoLTDDW.

The whole pipeline in one line

Source: AdventureWorks2022 (sales OLTP)→ stg: full and watermark extracts→ Dimensions: Date, Customer (SCD2)→ Fact: Orders (MERGE)→ DQ gate→ rpt views

Where this comes from

The warehouse design follows the LinkedIn Learning course Implementing a Data Warehouse with SQL Server 2022 (schemas, the Date/Customer/Orders star, the indexed view, columnstore and workload classification). This tutorial runs those exercises on SQL Server for Linux, fixes what breaks there, and wraps them in a production-style pipeline.
