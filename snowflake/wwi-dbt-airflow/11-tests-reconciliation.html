Tests & Reconciliation

Lab:dbt test+extract/reconcile.py123 tests and 7 reconciliation checks, all passing.

Two kinds of proof protect every number. dbt tests check that the model is internally sound: keys are unique, every fact points at a real dimension row. The reconciliation checks it against the outside world: the same counts and totals, computed in SQL Server and in Snowflake, must match exactly.

Since dbt 1.10, a generic test's parameters go under arguments:. The older form still runs but prints a deprecation warning for every test.

-- returns a row (and fails) if the mart lost or duplicated invoice lines on the way from Silver
with silver as (select count(*) n, sum(extended_price) incl, sum(tax_amount) tax, sum(line_profit) profit
                from {{ ref('stg_sales__invoice_lines') }}),
     mart   as (select count(*) n, sum(extended_price) incl, sum(tax_amount) tax, sum(line_profit) profit
                from {{ ref('mart_fact_sales_line') }})
select * from silver cross join mart
where silver.n <> mart.n or silver.incl <> mart.incl or silver.tax <> mart.tax or silver.profit <> mart.profit

Which tests run with which layer

The first time dbt test --select silver ran, 62 tests passed and one errored: the totals test above. It reads a Silver model, so dbt's default eager selection picked it up, but the mart it also reads didn't exist yet. The fix is one flag:

dbt test --select silver --indirect-selection cautious   # only tests whose models are ALL in Silver
dbt test --select gold   --indirect-selection cautious
dbt test --select mart_sales                             # default (eager): includes the cross-layer test

With cautious, a test runs only when every model it reads is selected. Cross-layer tests run once, with the last layer they touch.

Reconciliation: Snowflake against the source

("sales lines -> MART_SALES.FACT_SALES_LINE",
 "SELECT COUNT(*), SUM(ExtendedPrice), SUM(LineProfit) FROM Sales.InvoiceLines",                         # SQL Server
 "SELECT COUNT(*), SUM(extended_price), SUM(line_profit) FROM WWI_ANALYTICS.MART_SALES.FACT_SALES_LINE"), # Snowflake

Tests can't see what never arrived

Every dbt test passed even while Sales.Customers was empty in Bronze (Chapter 3): an empty table has no duplicate keys. Only a comparison with the source catches missing data. That is why the reconciliation runs at the end of every DAG run.

Key takeaways

  • dbt tests prove the model is consistent; the reconciliation proves it is complete and correct.
  • Use --indirect-selection cautious per layer; let cross-layer tests run with the last layer.
  • Compare exact decimals, and fail the run on any mismatch.
