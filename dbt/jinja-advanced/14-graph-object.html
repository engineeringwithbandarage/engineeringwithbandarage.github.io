The graph Object

Inside Jinja, graph gives you the whole manifest: every model, test, source, exposure and metric, with configs, columns and lineage. Macros can therefore reason about the project, not only the current model. That's the basis for documentation checks, automated grants and lineage tooling built in dbt itself.

Shape and availability

graph.nodes         unique_id → node dict   (models, tests, seeds, snapshots, analyses, operations)
graph.sources       unique_id → source dict
graph.exposures, graph.metrics, graph.groups, graph.semantic_models, graph.saved_queries

The nodes are the same dictionaries you saw in manifest.json. graph is only populated when execute is true, because during parsing the manifest it would describe doesn't exist yet. Always guard:

{% if execute %}
  {% set models = graph.nodes.values() | selectattr('resource_type', 'equalto', 'model') | list %}
  {{ log(models | length ~ ' models', info=True) }}
{% endif %}

Pattern 1: project-wide checks as an operation

{#- dbt run-operation check_documentation --args '{folders: [mart, rpt]}' -#}
{% macro check_documentation(folders=['mart', 'rpt']) %}
    {%- if not execute -%}{{ return('') }}{%- endif -%}
    {%- set problems = [] -%}
    {%- for node in graph.nodes.values()
          if node.resource_type == 'model' and node.package_name == project_name
             and node.fqn[1] in folders -%}
        {%- if not node.description -%}
            {%- do problems.append(node.name ~ ': missing model description') -%}
        {%- endif -%}
        {%- if node.columns | length == 0 -%}
            {%- do problems.append(node.name ~ ': no columns documented') -%}
        {%- endif -%}
        {%- set ns = namespace(tests=0) -%}
        {%- for t in graph.nodes.values()
              if t.resource_type == 'test' and node.unique_id in t.depends_on.nodes -%}
            {%- set ns.tests = ns.tests + 1 -%}
        {%- endfor -%}
        {%- if ns.tests == 0 -%}
            {%- do problems.append(node.name ~ ': has no tests') -%}
        {%- endif -%}
    {%- endfor -%}
    {%- for p in problems %}{{ log('✗ ' ~ p, info=True) }}{% endfor -%}
    {%- if problems -%}
        {{ exceptions.raise_compiler_error(problems | length ~ ' documentation problem(s)') }}
    {%- endif -%}
    {{ log('✓ documentation complete', info=True) }}
{% endmacro %}

Jinja has no built-in "list contains" test to use with selectattr, so counting tests uses a filtered loop and a namespace counter (chapter 03). Run this operation in CI and a missing description fails the build.

Pattern 2: grants for everything in a folder

{% macro grant_reporting(role='reporting') %}
    {%- if not execute -%}{{ return('') }}{%- endif -%}
    {%- set schemas = [] -%}
    {%- for node in graph.nodes.values()
          if node.resource_type == 'model' and 'mart' in node.fqn and node.schema not in schemas -%}
        {%- do schemas.append(node.schema) -%}
    {%- endfor -%}
    {%- for s in schemas %}
    grant usage on schema {{ adapter.quote(s) }} to {{ role }};
    grant select on all tables in schema {{ adapter.quote(s) }} to {{ role }};
    {%- endfor %}
{% endmacro %}

Pattern 3: walking lineage

Which stg tables does dimemployee ultimately depend on? This macro walks depends_on upwards until it reaches sources:

{% macro upstream_sources(unique_id) %}
    {%- set seen = [] -%}
    {%- set found = [] -%}
    {%- set queue = [unique_id] -%}
    {%- for _ in range(500) if queue -%}            {#- bounded loop instead of while -#}
        {%- set uid = queue.pop(0) -%}
        {%- if uid not in seen -%}
            {%- do seen.append(uid) -%}
            {%- if uid.startswith('source.') -%}
                {%- do found.append(graph.sources[uid].schema ~ '.' ~ graph.sources[uid].name) -%}
            {%- elif uid in graph.nodes -%}
                {%- do queue.extend(graph.nodes[uid].depends_on.nodes) -%}
            {%- endif -%}
        {%- endif -%}
    {%- endfor -%}
    {{ return(found | unique | sort) }}
{% endmacro %}

Why the odd loop

Jinja has no while. The filter on the loop header (if queue) is evaluated once per item of range(500), and the queue is changed in place, so this behaves like a bounded while queue:. Breadth-first search over the manifest, written entirely in Jinja.

Use it to make the reconcile check targeted: before building dimemployee, confirm that every upstream stg table was loaded in this run:

{% macro assert_upstream_loaded() %}
    {%- if not execute -%}{{ return('') }}{%- endif -%}
    {%- set tables = [] -%}
    {%- for s in upstream_sources(model.unique_id) if s.startswith('stg.') -%}
        {%- do tables.append(s[4:]) -%}            {#- 'stg.employee' → 'employee' -#}
    {%- endfor -%}
    {%- set q -%}
        select count(distinct stg_table) from {{ source('audit', 'etl_table_load') }}
        where run_id = {{ var('run_id') }}
          and stg_table in ({% for t in tables %}'{{ t }}'{{ ',' if not loop.last }}{% endfor %})
    {%- endset -%}
    {%- set n = run_query(q).columns[0].values()[0] | int -%}
    {%- if n != tables | length -%}
        {{ exceptions.raise_compiler_error(model.name ~ ': only ' ~ n ~ ' of ' ~ (tables | length) ~ ' upstream stg tables loaded in run ' ~ var('run_id')) }}
    {%- endif -%}
{% endmacro %}

selected_resources

selected_resources is the list of unique_ids selected for the current invocation. Combined with graph, it lets an on-run-end hook act only on what this run touched, for example granting only on selected models or refreshing statistics only for rebuilt tables.

Performance

  • Iterating graph.nodes is cheap once. Doing it inside every model of a large project means it runs once per model per compile, which adds up. Prefer operations and on-run-end hooks for project-wide logic.
  • Treat graph as read-only. Changing it has no defined effect.

Key takeaways

  • graph exposes the manifest to Jinja, but only when execute is true.
  • Filters (selectattr, map), filtered loops and bounded loops are enough for real graph algorithms.
  • Typical uses are documentation gates, grants, lineage-aware checks and YAML-driven SQL.
  • Keep project-wide logic in operations and hooks, not in every model.

      if n.resource_type == 'model' and 'source.dwlab.stg.employee' in n.depends_on.nodes %}
  {% do readers.append(n.name) %}
{% endfor %}
