Chapter 06 · Macros

Writing Macros

Macros are functions that generate text or return values. This chapter covers the full calling convention (positional and keyword arguments, defaults, varargs/kwargs, caller()) and then refactors your dimemployee model with three reusable macros.

~35 min read Lab: refactoring dimemployee

Anatomy

{#- Audit columns shared by all dimension models.
    incremental: true when rendering the incremental branch (a "t" alias for the target exists). -#}
{% macro audit_columns(incremental=false, target_alias='t') -%}
    {%- set rid = var('run_id') -%}
    {%- if incremental -%}
    coalesce({{ target_alias }}.dw_first_run_id, {{ rid }})   as dw_first_run_id,
    {{ rid }}                                                 as dw_last_run_id,
    coalesce({{ target_alias }}.dw_inserted_at, now())        as dw_inserted_at,
    {%- else -%}
    {{ rid }}                                                 as dw_first_run_id,
    {{ rid }}                                                 as dw_last_run_id,
    now()                                                     as dw_inserted_at,
    {%- endif %}
    now()                                                     as dw_updated_at
{%- endmacro %}
  • File placement: any .sql file under macro-paths. A file can hold several macros, and the file name doesn't matter, though matching it to the main macro helps people find it.
  • Names are global inside the project. Two macros with the same name in one project cause a parse error.
  • Output is whatever the body renders. Calling {{ audit_columns(incremental=is_incremental()) }} pastes the columns into the model.

Arguments

{% macro m(a, b=2, c=none) %}…{% endmacro %}

{{ m(1) }}               {# a=1, b=2, c=none #}
{{ m(1, 3) }}            {# positional #}
{{ m(1, c='x') }}        {# keyword #}
{{ m(a=1, b=3, c='x') }} {# all keyword (clearest at call sites) #}
{{ m() }}                {# a is undefined inside — NOT an error until used #}
{{ m(1, d=4) }}          {# error: macro 'm' takes no keyword argument 'd' #}

Missing arguments don't fail at the call

Jinja doesn't require arguments, so a missing one is simply undefined until it's used. Validate the ones that matter (see below), especially in macros other people will call.

varargs and kwargs

If a macro uses the special names varargs or kwargs in its body, Jinja accepts extra positional or keyword arguments and collects them there:

{% macro coalesce_all() -%}
    coalesce({{ varargs | join(', ') }}{% if kwargs.get('default') is not none %}, {{ kwargs['default'] }}{% endif %})
{%- endmacro %}

{{ coalesce_all('middlename', "''") }}                → coalesce(middlename, '')
{{ coalesce_all('phone', 'emergencycontactphone', default="'n/a'") }}

Returning values

As chapter 01 explained, {{ return(x) }} hands back the object x. Use it for any macro that computes data rather than SQL text:

{#- Columns that define a "change" for an SCD2 dimension: every column except keys and audit fields. -#}
{% macro scd2_hash_columns(all_columns, exclude=[]) %}
    {%- set skip = ['employeekey', 'parentemployeekey', 'row_hash', 'startdate',
                    'dw_first_run_id', 'dw_last_run_id', 'dw_expired_run_id',
                    'dw_inserted_at', 'dw_updated_at'] + exclude -%}
    {{ return(all_columns | reject('in', skip) | list) }}
{% endmacro %}

caller() and {% call %} blocks

A {% call %} block passes a block of template to a macro, which renders it where it calls caller(). This is how dbt's own statement macro receives its SQL, and it's how you write "wrapper" macros:

{% macro timed(label) -%}
    -- start {{ label }}
    {{ caller() }}
    -- end {{ label }}
{%- endmacro %}

{% call timed('load employee versions') %}
    select * from {{ ref('int_employee_department_versions') }}
{% endcall %}

A real use is a macro that wraps any SELECT in a "changed rows only" filter. The caller supplies the SELECT and the macro supplies the comparison:

{% macro only_changed(key_cols, hash_col='row_hash') -%}
    {%- if is_incremental() -%}
    select s.* from ( {{ caller() }} ) s
    left join {{ this }} t
           on {% for k in key_cols %}t.{{ k }} = s.{{ k }}{% if not loop.last %} and {% endif %}{% endfor %}
    where t.{{ key_cols[0] }} is null
       or t.{{ hash_col }} is distinct from s.{{ hash_col }}
    {%- else -%}
    {{ caller() }}
    {%- endif -%}
{%- endmacro %}

Recursion

Macros can call themselves. That's handy for walking nested structures, such as a management hierarchy described in YAML, or for building nested SQL expressions:

{#- nested_coalesce(['a','b','c']) → coalesce(a, coalesce(b, c)) — contrived, but shows the pattern -#}
{% macro nested_coalesce(cols) -%}
    {%- if cols | length == 1 -%}
        {{ cols[0] }}
    {%- else -%}
        coalesce({{ cols[0] }}, {{ nested_coalesce(cols[1:]) }})
    {%- endif -%}
{%- endmacro %}

Recursion depth is limited by Python's recursion limit, and each level adds dbt wrapper frames. Keep recursion shallow, and prefer loops for long lists.

Namespacing and calling other macros

{{ record_dim_stats(scd2=true) }}        {# root project (or current package) #}
{{ dwlab.record_dim_stats(scd2=true) }}  {# explicit — required when calling from another package #}
{{ dbt.current_timestamp() }}            {# dbt's cross-database macro #}
{{ dbt_utils.star(ref('x')) }}           {# an installed package #}

Validating input

{% macro scd2_key_join(key_cols, left='t', right='s') %}
    {%- if key_cols is string -%}{%- set key_cols = [key_cols] -%}{%- endif -%}
    {%- if key_cols is not iterable or key_cols | length == 0 -%}
        {{ exceptions.raise_compiler_error("scd2_key_join: key_cols must be a non-empty list, got " ~ key_cols) }}
    {%- endif -%}
    {%- for k in key_cols -%}
        {{ left }}.{{ k }} = {{ right }}.{{ k }}{% if not loop.last %} and {% endif %}
    {%- endfor -%}
{% endmacro %}

Accepting both a single string and a list, as unique_key does, makes a macro much more pleasant to use.

Documenting macros

version: 2
macros:
  - name: record_dim_stats
    description: "Post-hook: writes this run's row statistics for a dimension to audit.dim_load_stats."
    arguments:
      - name: scd2
        type: boolean
        description: "true for Type 2 dimensions (reports inserted/updated/expired/current rows)"
  - name: scd2_key_join
    description: "Renders `t.k1 = s.k1 and t.k2 = s.k2` for a list of key columns."
    arguments:
      - name: key_cols
        type: list[string] | string

These descriptions appear in dbt docs and in manifest.json, so other people can find your macros.

Putting it together: dimemployee, refactored

select
    {% if is_incremental() -%}
    coalesce(t.employeekey, nextval('{{ this.schema }}.dimemployee_key_seq')) as employeekey,
    {%- else -%}
    nextval('{{ this.schema }}.dimemployee_key_seq')                           as employeekey,
    {%- endif %}
    null::bigint as parentemployeekey,
    s.employeenationalidalternatekey,
    …,
    s.row_hash,
    {% if is_incremental() -%}
    case when s.status is null and t.status = 'Current' then {{ var('run_id') }}
         else t.dw_expired_run_id end as dw_expired_run_id,
    {%- else -%}
    null::integer as dw_expired_run_id,
    {%- endif %}
    {{ audit_columns(incremental=is_incremental()) }}
from src s
{% if is_incremental() -%}
left join tgt t on {{ scd2_key_join(['employeenationalidalternatekey', 'startdate']) }}
where t.employeekey is null
   or t.row_hash is distinct from s.row_hash
{%- endif %}

One side effect: the audit columns now come out in a different order (dw_expired_run_id moves before the others). The merge matches columns by name, so incremental runs aren't affected, but a fresh build creates the table with the new order. Make this change together with a planned rebuild.

The model now states what is special about this dimension, and the shared macros handle the rest. Chapter 18 takes this further, so that a complete SCD2 dimension is generated from a few lines of config.

Key takeaways

  • Macros output text by default. Use return() for data.
  • Arguments are lenient: defaults are optional, missing arguments are just undefined, and extra keyword arguments are an error unless the macro uses kwargs.
  • {% call %} + caller() pass a block of template into a macro, which is good for wrappers.
  • Validate input, accept a string or a list, and document macros in YAML.

Exercises

1 · Column list with aliases

Write select_list(cols, alias='s') that renders s.a, s.b, s.c, one per line, without a trailing comma.

Answer 
{% macro select_list(cols, alias='s') -%}
    {%- for c in cols %}
    {{ alias }}.{{ c }}{{ "," if not loop.last }}
    {%- endfor %}
{%- endmacro %}
2 · Why is the list a string?

{% set keys = my_keys() %}{{ keys | length }} prints 57. What's wrong with my_keys?

Answer

It writes the list, for example {{ ['a','b'] }}, instead of returning it, so the caller receives the string "['a', 'b']" with whitespace around it. Use {{ return([...]) }}.
