Appendix C

Glossary

Terms used across both tutorials, with the chapter where each is explained in depth. I = dbt Core Internals, J = Advanced dbt Jinja.

TermMeaningSee
AdapterThe database-specific plugin (here dbt-postgres): credentials, connections, a few Python methods and postgres__ macrosI-02
agate.TableThe table type returned by run_query, with .columns, .rows and .column_namesJ-07
ArtifactA JSON file dbt writes to target/: manifest, run_results, catalog, sourcesI-08
ContextThe set of names available while a template renders. It differs for YAML, parse, runtime, hooks and operationsI-06, J-04
DeferralResolving refs to unbuilt models against another environment's manifest (--defer --state)I-08
DispatchChoosing a macro implementation by adapter and search order (adapter.dispatch)J-10
executeFalse while parsing, true while compiling/running. Guards anything that needs the databaseI-01, J-01
Generic testA parameterised {% test %} macro, attached to many resources from YAMLJ-13
GraphQueueThe dependency-aware queue that hands nodes to worker threadsI-05
HookSQL run around a model (pre_hook/post_hook) or an invocation (on-run-start/end)J-09
Indirect selectionIncluding tests because their parents were selected (eager, buildable, cautious, empty)I-05
InvocationOne dbt command execution, identified by invocation_idI-01
MacroA Jinja function. It outputs text, or returns an object with return()J-06
ManifestThe parsed project: every node, source, macro and config, plus lineageI-04
MaterializationThe macro that decides how a model is built (table, view, incremental, custom)I-07, J-12
metaA free-form config dict, the forward-compatible place for your own settingsJ-04, J-18
Namespace (Jinja)namespace(): an object whose attributes can be changed inside loopsJ-03
Namespace (package)The package-name prefix for macros (dbt_utils.star) and the dispatch namespaceJ-10, J-16
NodeOne resource in the manifest with a unique_id: model, test, seed, snapshot, source …I-04
Parse contextThe context used while parsing, where refs are recorded and queries don't runI-04
Partial parsingRe-parsing only changed files, using partial_parse.msgpackI-04
RelationAn object for a database object (database, schema, identifier, type), returned by ref/source/thisJ-05
Relation cachedbt's in-memory list of existing relations, filled before a runI-07
RuntimeConfigThe merged project + profile + flags object that every component readsI-03
RunnerThe class that compiles and executes one node (ModelRunner, TestRunner, …)I-07
SandboxJinja's restricted environment: no imports, no private attributesI-06
SCD2Slowly Changing Dimension Type 2: history kept as versions with validity rangesJ-12, J-18
SelectorA --select expression or a named YAML selector that resolves to unique_idsI-05
Singular testA .sql file in tests/ that returns failing rowsJ-13
StateSaved artifacts used for comparison (state:modified, result:error)I-08
Static parserdbt-extractor: reads simple ref/source/config without rendering JinjaI-04
TaskThe class behind a command (RunTask, BuildTask, …)I-07
Unit testA YAML-defined test of model logic with mocked inputs (1.8+)J-13
Whitespace control{%- -%} trimming of the whitespace around tagsJ-02
