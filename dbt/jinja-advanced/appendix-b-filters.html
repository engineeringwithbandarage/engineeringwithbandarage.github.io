Filter Reference

Filters are applied with | and can be chained. These are the Jinja 3 built-ins that are actually useful when generating SQL, grouped by task, plus the filters dbt adds itself.

Stable output

When generating SQL from a dict, iterate with | dictsort, or a sorted list of keys, so that the compiled SQL is identical from run to run. Stable output gives you clean diffs, reliable state:modified comparisons, and makes the capstone's "compare compiled SQL" rollout possible.

Tests for is, select and selectattr

defined, undefined, none, boolean, true, false, integer, float, number, string, mapping, iterable, sequence, callable, sameas, in, eq/equalto/==, ne/!=, lt/<, le/<=, gt/>, ge/>=, divisibleby, even, odd, lower, upper, escaped, filter, test.

{{ cols | select('ne', 'row_hash') | list }}
{{ nodes | selectattr('config.materialized', 'in', ['table', 'incremental']) | list }}
{{ values | reject('none') | list }}

No "contains" or "match" tests

Jinja has no built-in test for "list contains x" or regex matching. Use a filtered loop ({% for n in nodes if x in n.depends_on.nodes %}) or modules.re inside a loop.
